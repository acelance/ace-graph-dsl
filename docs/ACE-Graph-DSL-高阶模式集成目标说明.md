## 0. 先记这一句

| 层 | 管什么 | 产品形态 |
|----|--------|----------|
| **图级（ACE 已有）** | **业务阶段之间**怎么连：串行、扇出、条件跳、子图 | 画布上的**边与多节点** |
| **节点内（SAA 要集成）** | **某一个阶段内部**多个子 Agent 怎么协作：顺序、并行、路由、循环 | 画布上的**一个** `SAA_WORKFLOW` 复合节点 |

> **图管阶段，节点管内协作。**  
> 「对齐 Vertical / SAA 记忆语义」只对齐 role / extras；落盘节奏仍按 ace-graph **每节点即时 remote**（见项目记忆约定）。本文件只澄清编排分层，不改记忆时机。

四种模式 **都不是**「替代图边」，而是「在图的某一节点内部，提供成套多智能体协作模式」。

## 1. 两层并行/编排，为什么必须分开说

效果上看，图级「多条边串起来」和节点内 Sequential，都能做出「先 A 再 B」；图级 FanOut 和节点内 Parallel，都能「两边一起跑再汇」。  
但 **抽象层、资产形态、复用方式、观测粒度** 不同——混用会在设计器文案、技术方案、评审口径上反复打架。

```text
┌──────────────────────────────────────────────────────────────┐
│  ACE 图（主编排 / 资产）                                      │
│                                                              │
│   START → 阶段节点₁ → 阶段节点₂ → … → END                    │
│              │                                               │
│              │  若阶段节点₂ = SAA_WORKFLOW                    │
│              ▼                                               │
│         ┌────────────────────────────────────┐               │
│         │  节点内：SAA FlowAgent 模式          │               │
│         │  Sequential / Parallel /            │               │
│         │  Routing / Loop + subAgents[]       │               │
│         └────────────────────────────────────┘               │
└──────────────────────────────────────────────────────────────┘
```

| 维度 | 图级原语（已有） | 节点内模式（集成目标） |
|------|------------------|------------------------|
| 可见性 | 设计器上多个节点、多条边 | 通常只看到 **一个** 复合节点 |
| 配置位置 | 边属性（`normal` / `parallel` / `conditional`）+ 各节点 `agentSpec` | 节点 `saaSpec.pattern` + `subAgents[]` |
| 复用单位 | 整段子图 / 发布版本 | 「协作模式」模板（如「生成→评分」） |
| 状态契约 | 下游边依赖各节点 `outputKey` | 对外主要暴露父节点 `inputKeys` / `outputKey`；子键为内部协作 |
| 典型职责 | 跨业务阶段、HITL、版本发布主叙事 | 单阶段内固定多智能体套路 |

**禁止口径：**

1. 禁止说「接了 ParallelAgent 就等于有了图级并行」——图级并行 ACE **已经有**。  
2. 禁止说「有了图级 FanOut 就不需要 ParallelAgent」——二者解决的复用与封装问题不同。  
3. 禁止把整张业务图（如 `ztc-service-agent`）收成一个 `SequentialAgent`——会丢掉图资产与阶段治理。

## 2. Sequential（顺序）

### 2.1 SAA 模式在管什么

`SequentialAgent`：按 `subAgents` **数组顺序**执行；前序子 Agent 写入的 state 键可供后序 `{placeholder}` / 输入使用；整段结束后再写回父节点约定结果。

管的是：**一个复合节点内部的「流水线协作」**，不是画布上「节点 A → 节点 B」那条业务边。

### 2.2 ACE 已有的「看起来像 Sequential」

| ACE 图级能力 | 说明 |
|--------------|------|
| 多条 `normal` 边串多个 `GENERIC_AGENT` | 例如：意图 → 业务 → 输出 |
| 子图 `SUBGRAPH` | 把一段串行流程封装成子图节点 |

业务样例「意图 → 业务 → 输出」语义像 Sequential，但是 **DSL 边编排**，不是 `SequentialAgent`。

### 2.3 ACE 集成目标（节点内）

| 项 | 目标 |
|----|------|
| 产品形态 | `category=SAA_WORKFLOW`，`pattern=SEQUENTIAL` |
| 行为 | 子 Agent 有序执行；子 `outputKey` 向后传递；父 `outputKey` 对外交付 |
| 与图级分工 | **跨阶段主叙事继续用图边**；仅当「固定多步协作希望少画边、可当模板复用」时用 Sequential 复合节点 |
| 设计器文案建议 | 「节点内顺序协作」；不要写成「替代图上的串行边」 |

### 2.4 拓扑对照

**图级串行（已有，应继续作为主叙事）：**

```text
START → 意图节点 → 业务节点 → 输出节点 → END
```

**节点内 Sequential（集成目标）：**

```text
START → … → 节点「SQL 质检」(SAA_WORKFLOW / SEQUENTIAL)
                    ├─ 子Agent sql_generator → 写 sql
                    └─ 子Agent sql_rater     → 写 score
              → 父 outputKey = sql_score
        → 下游阶段 → END
```

画布上「SQL 质检」是 **一个** 节点；并发/顺序发生在节点内部。

### 2.5 何时用哪一层

| 场景 | 优先 |
|------|------|
| 意图识别、业务处理、最终话术是 **不同业务阶段**，要版本、HITL、分权限 | **图边串行** |
| 「生成 SQL → 评分」是 **同一阶段内的固定套路**，希望拖一个节点复用 | **Sequential 复合节点** |
| 整段流程既要发布治理又要内部套路 | **图边包阶段 + 阶段内 Sequential**（叠用，不互相替代） |

## 3. Parallel（并行）

### 3.1 SAA 模式在管什么

`ParallelAgent`：同一输入下 **并发** 跑多个子 Agent，再按策略 **合并** 结果，写入约定键。

管的是：**节点内部多专家协作**，不是画布上两条分支业务节点。

### 3.2 ACE 已有的「看起来像 Parallel」

| ACE 图级能力 | 说明 |
|--------------|------|
| 边 `parallel=true` + `FanOutNodeAction` | 图上多个节点扇出并行，再汇合 |
| 设计器「并行边」 | 拓扑可见、可发布、可接后续 HITL / 条件 |

### 3.3 ACE 集成目标（节点内）

| 项 | 目标 |
|----|------|
| 产品形态 | `category=SAA_WORKFLOW`，`pattern=PARALLEL` |
| 行为 | 子 Agent 并行；合并策略写入父 `outputKey`（及约定子键） |
| 与图级分工 | **FanOut = 图管阶段并行**；**ParallelAgent = 节点管内协作并行** |
| 设计器文案建议 | 图级：「阶段并行 / FanOut」；节点内：「多智能体并行协作」——分开展示 |

### 3.4 拓扑对照

**图级 FanOut（已有）：**

```text
START → 调度
           ├─[parallel]→ 节点「客服话术」 ─┐
           └─[parallel]→ 节点「排查清单」 ─┴→ 汇总 → END
```

并行的是 **两个图节点（两个阶段）**。

**节点内 Parallel（集成目标）：**

```text
START → 节点「并行调研」(SAA_WORKFLOW / PARALLEL)
              ├─ 子Agent 网搜
              ├─ 子Agent 库查
              └─ merge → 写 research_result
        → 分析节点 → END
```

画布上只有一个「并行调研」；并发在 **子 Agent** 层。

### 3.5 何时用哪一层

| 场景 | 优先 |
|------|------|
| 两个阶段结果都要独立落库 / 独立流式展示 / 独立 HITL | **图级 FanOut** |
| 同一调研阶段内多个专家角色，对外只暴露一个汇总键 | **Parallel 复合节点** |
| 两个阶段并行，且某一阶段内部还要多专家 | 可叠用（中期不必一上来做深） |

### 3.6 易混点（必须写进评审口径）

- 「ACE 的目标：节点内并行」≠ 重做 FanOut。  
- 「与图级 `parallel=true` 分层」= **职责分层**，不是二选一淘汰。

## 4. Routing（路由）

### 4.1 SAA 模式在管什么

`LlmRoutingAgent` / Routing 类 FlowAgent：根据输入（常配合 LLM）在 **多个子 Agent 中选一条（或一组）路径** 执行，再写回结果。

管的是：**节点内部的意图分流 / 专家分派**，候选方是 `subAgents[]`，不是画布上另一条条件边目标节点。

### 4.2 ACE 已有的「看起来像 Routing」

| ACE 图级能力 | 说明 |
|--------------|------|
| 条件边 `conditional` | dispatcher / 脚本按 state 跳到不同下游 **图节点** |
| 设计器条件边 | 阶段级分流，拓扑可见 |

注意：平台里另有「Skill 查询路由」等业务解析能力，那是 **入口/技能选择**，既不是图条件边，也不是 SAA Routing 复合节点——三者不要混称「Routing」。

### 4.3 ACE 集成目标（节点内）

| 项 | 目标 |
|----|------|
| 产品形态 | `category=SAA_WORKFLOW`，`pattern=ROUTING` |
| 行为 | 路由器（模型或规则）选择子 Agent；执行后写父 `outputKey` |
| 与图级分工 | **条件边 = 图级阶段路由**；**RoutingAgent = 节点内专家路由** |
| 设计器文案建议 | 图级：「条件跳转 / 阶段分流」；节点内：「专家路由（节点内）」 |

### 4.4 拓扑对照

**图级条件边（已有）：**

```text
START → 意图节点
           ├─[cond: hr]→ HR 业务节点 → …
           ├─[cond: it]→ IT 业务节点 → …
           └─[cond: else]→ 兜底节点 → …
```

分流目标是 **不同业务阶段节点**（可挂不同 MCP、不同 HITL、不同发布策略）。

**节点内 Routing（集成目标）：**

```text
START → … → 节点「专家台」(SAA_WORKFLOW / ROUTING)
                  路由器 → 选 hr | it | finance（均为 subAgent）
                  → 写 route_result
        → 统一输出阶段 → END
```

分流目标是 **同一复合节点内的子 Agent**；下游图边仍只看见父节点输出。

### 4.5 何时用哪一层

| 场景 | 优先 |
|------|------|
| 分流后各支路是 **不同业务阶段**（流程分叉、审批、不同输出形态） | **图条件边** |
| 分流后只是 **同一阶段内换专家**，对外仍是一步「答完」 | **Routing 复合节点** |
| 先图级大类分流，再在某一支路内专家细分 | 可叠用 |

## 5. Loop（循环）

### 5.1 SAA 模式在管什么

`LoopAgent`：在退出条件未满足且未超过 `maxIterations` 时，重复执行 body（单子 Agent 或内嵌 Sequential），直到达标或触顶。

管的是：**节点内部的「达标再停」协作**，不是图上用边画一个自环拓扑当主叙事。

### 5.2 ACE 已有的「看起来像 Loop」

| ACE 现状 | 说明 |
|----------|------|
| GenericAgent 内工具循环 / ReAct 式自建循环 | **单 Agent 调工具**，不是多 Agent Loop 模式 |
| 脚本自环、手工边自环（若有） | 弱、非一等「Loop 模式」；难复用「生成→评分→未达标再来」 |
| 图级反复跳回某节点 | 一般不推荐作业务主叙事；难控最大轮次与退出语义 |

### 5.3 ACE 集成目标（节点内）

| 项 | 目标 |
|----|------|
| 产品形态 | `category=SAA_WORKFLOW`，`pattern=LOOP` |
| 行为 | 退出条件键 + 比较符 + 阈值 + `maxIterations`（须有上限防失控） |
| body | 单子 Agent，或内嵌 Sequential（如「生成 → 评分」一轮） |
| 与图级分工 | **Loop 补齐目前较弱的一等循环模式**；不要用「图边自环」冒充 Loop 产品能力 |
| 设计器文案建议 | 「节点内循环直至达标」；突出最大轮次与退出条件必填 |

### 5.4 拓扑对照

**图级硬拧自环（不推荐当产品主能力）：**

```text
… → 生成节点 → 评分节点 ─┬─[score 达标]→ 下游
                         └─[未达标]→ 回到生成节点（难统一 maxIterations / 轨迹）
```

**节点内 Loop（集成目标）：**

```text
START → … → 节点「SQL 迭代质检」(SAA_WORKFLOW / LOOP)
                  body: Sequential(生成 → 评分)
                  exit: score > 0.5，maxIterations = 3
                  → 写 sql_score
        → 下游 → END
```

对外一步；轮次、退出、触顶失败语义由模式统一。

### 5.5 何时用哪一层

| 场景 | 优先 |
|------|------|
| 单 Agent 反复调工具直到任务结束 | GenericAgent / 未来 ReactAgent（**工具循环**，不是 Loop 多 Agent） |
| 多 Agent「生成→评判→再生成」直到阈值 | **Loop 复合节点** |
| 业务流程上「人工驳回后重回某阶段」 | **图边 + HITL**，不是 LoopAgent |

## 6. 四模式对照总表

| 模式 | SAA 管什么（节点内） | ACE 已有近似（图级） | 集成后 ACE 目标一句话 | 是否互相替代 |
|------|----------------------|----------------------|------------------------|--------------|
| **Sequential** | 子 Agent 固定顺序协作 | `normal` 边串多节点 / 子图 | 单阶段内「流水线」封装为一个复合节点 | **否**；跨阶段仍用边 |
| **Parallel** | 子 Agent 并发 + 合并 | `parallel` + `FanOutNodeAction` | 单阶段内多专家并行协作 | **否**；阶段并行仍用 FanOut |
| **Routing** | 子 Agent 间意图/规则分流 | `conditional` 条件边 | 单阶段内专家台路由 | **否**；阶段分叉仍用条件边 |
| **Loop** | 退出条件 + 最大轮次重复 body | 工具自循环 / 弱自环边 | 一等「达标循环」协作模式 | **否**；HITL 驳回回流用图+HITL |

## 7. 设计器与评审防偏清单

设计器 / 方案评审出现下列表述时，按本文件纠正：

| 偏差表述 | 纠正 |
|----------|------|
| 「Parallel 集成 = 做图并行」 | 图并行已有；集成的是 **节点内** Parallel |
| 「有了 FanOut 就不用 Parallel」 | FanOut 管阶段；Parallel 管节点内协作与模板复用 |
| 「Sequential 就是把 ztc 三节点合成一个」 | **禁止**整图收成 Sequential；ztc 主叙事保持图边 |
| 「Routing 就是条件边换个实现」 | 条件边跳的是 **图节点**；Routing 选的是 **subAgent** |
| 「Loop 用边指回自己就行」 | 产品一等能力是 Loop 模式（退出条件 + maxIterations），不是裸自环 |
| 「四种模式替代画布」 | 画布仍是主编排；四种模式是 **可选高阶节点** |

建议 UI 分组：

- **图编排**：串行边 / 并行边（FanOut）/ 条件边 / 子图 / HITL  
- **高阶多智能体（节点内）**：Sequential / Parallel / Routing / Loop  

两组文案并列，禁止合并成一个「并行」菜单。

## 9. 一句话验收口径（给产品 / 研发共用）

集成 Sequential / Parallel / Routing / Loop 成功的标志是：

> 业务同学能在设计器里拖入 **一个** 高阶节点，配置 pattern 与子 Agent，完成「顺序 / 并行 / 路由 / 循环」协作；  
> 同时仍能用 **图边** 做跨阶段串行、FanOut、条件跳与 HITL；  
> 且任何人都能说清：**前者是节点管内协作，后者是图管阶段。**
